### 1. DateTime Parsing Duplicado vs `TimestampUtils` Existente

**Problema:** El archivo `lib/utils/timestamp_utils.dart` YA existe con `TimestampUtils.toDateTime()`, pero los modelos ignoran esta utilidad y re-implementan `_parseDateTime()` localmente.

**Ubicaciones del código duplicado:**
- `lib/models/chat.dart:111-117` - implementación local de `_parseDateTime()`

```dart
// ❌ DUPLICADO en chat.dart:111-117
static DateTime? _parseDateTime(dynamic value) {
  if (value == null) return null;
  if (value is Timestamp) return value.toDate();
  if (value is DateTime) return value;
  if (value is String) return DateTime.tryParse(value);
  return null;
}
```

```dart
// ✅ YA EXISTE en utils/timestamp_utils.dart:19-37
static DateTime? toDateTime(dynamic value) {
  if (value == null) return null;
  if (value is DateTime) return value;
  if (value is Timestamp) return value.toDate();
  if (value is String) { ... }
  if (value is int) { ... }
  return null;
}
```

**Diferencia:** `TimestampUtils.toDateTime()` también soporta `int` (milliseconds), es más completo.

**Impacto:** ~50+ archivos de modelos potencialmente afectados.

**Fix recomendado:**
```dart
// En todos los modelos, cambiar:
createdAt: _parseDateTime(data['createdAt']) ?? DateTime.now(),

// A:
createdAt: TimestampUtils.toDateTime(data['createdAt']) ?? DateTime.now(),
```
