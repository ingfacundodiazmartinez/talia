THE PROBLEM (SUMMARY)
================================================================================

CallListenerService works perfectly for the FIRST call but stops detecting
new calls after the first session.

ROOT CAUSE:
The Firestore listener is PERMANENTLY CANCELLED with no mechanism to restart it.

TECHNICAL DETAILS:
1. CallListenerService creates _foregroundCallSubscription in initialize()
2. This subscription is cancelled in dispose()
3. dispose() is called when TaliaApp is disposed (during navigation/role change)
4. No code path re-calls initialize() after disposal
5. The _isListening flag remains false forever
6. Subsequent calls are never detected

TIMELINE:
T=0s   : App starts → Listeners initialized ✅
T=30s  : First call arrives → Detected ✅
T=2m   : User navigates back → dispose() called → Listeners cancelled ❌
T=2m30s: Second call arrives → NOT detected ❌

WHERE IT HAPPENS:
- main.dart:664-665 (TaliaApp.dispose() calls disposeGlobalListeners())
- calls_orchestrator.dart:801 (_listenerService.dispose())
- call_listener_service.dart:63 (_foregroundCallSubscription?.cancel())

KEY INSIGHTS
================================================================================

1. DESIGN ISSUE:
   CallListenerService lifecycle is tied to TaliaApp widget.
   When TaliaApp is disposed/recreated, listeners die.
   Should be independent singleton with auto-recovery.

2. NAVIGATION ISSUE:
   pushNamedAndRemoveUntil('/', (route) => false) aggressively clears stack.
   This can trigger unexpected disposals.
   Should use popUntil() for safer navigation.

3. INITIALIZATION ISSUE:
   initState() only called once when widget created.
   If TaliaApp reused, initState() not called.
   Need explicit re-initialization path after disposal.

4. GUARD CONDITION ISSUE:
   if (_isListening) { return; } prevents re-initialization.
   But only helps if initialize() is called.
   If not called, listener stays dead forever.

5. CALLBACK ISSUE:
   onCallDetected nullified during dispose.
   No way to know what the original callback was.
   Need to store callbacks for recovery.
