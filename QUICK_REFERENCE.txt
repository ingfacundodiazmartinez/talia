DEPENDENCY INJECTION ORDER (CRITICAL):
─────────────────────────────────────────────────────────────────────────────
1. Firebase instances (Firestore, Auth, Storage)
   ↓
2. Repositories (need Firebase instances)
   ↓
3. Managers (some need Repositories)
   ↓
4. Services (depend on Repos + Managers)

KEY PATTERNS:
─────────────────────────────────────────────────────────────────────────────
✓ Service Specialization
  Each service handles ONE domain (creation, approval, retrieval, viewing)
  NO service does multiple domains

✓ Manager Independence  
  Managers don't call each other
  Only services coordinate between managers

✓ Repository Purity
  Repositories: ONLY Firestore access
  ZERO business logic allowed

✓ Cloud Functions for Security
  Client calls Cloud Function
  Server validates permissions
  Client never creates/modifies directly

✓ Optimistic UX
  Add to cache immediately
  Update server asynchronously
  Rollback on error

✓ Dual Reactive Sources
  Cache stream (immediate)
  Firestore stream (authoritative)
  UI subscribes to both

REAL EXAMPLES:
─────────────────────────────────────────────────────────────────────────────
Cache + Firestore:
  - Cache emits immediately
  - Firestore emits fresh data
  - UI subscribes to both, gets updates as they arrive

Cloud Functions:
  - Client calls function
  - Server validates permissions
  - Client updates cache only if success
  - No way to hack from client

Optimistic UX:
  - Story appears in UI immediately
  - Upload happens in background
  - If error: story removed from cache
  - User sees instant response
