STORY FILTERING ANALYSIS - EXECUTIVE SUMMARY
=============================================

CRITICAL FINDING:
The user was correct. Story visibility is controlled by:
1. APPROVED CONTACTS (bidirectional contact relationships)
2. PARENT-CHILD relationships (unidirectional authority)
3. Block status (bidirectional blocking)

NOT by GROUPS (which are for chat, not story visibility).

==============================================================================
THE CORRECT FILTERING LOGIC
==============================================================================

A user CAN SEE a story if:

For Regular Contacts:
  1. Story is from an APPROVED CONTACT (status='approved' in contacts collection)
  2. No block exists between the users (bidirectional check)
  3. Story status is 'approved'
  4. Story is not expired (>24 hours)
  5. Story visibility is 'temporary' (feed) or 'permanent' (profile)
  
For Parent-Child Relationships:
  1. User is the parent, child is in linkedChildrenIds
  2. No block exists between them
  3. Story can be any status: approved, pending, rejected
  4. Story is not expired
  
For Own Stories:
  1. User always sees their own stories
  
A user CANNOT SEE:
  - Stories from non-contacts
  - Stories with status='uploading' (except creator)
  - Expired stories (>24 hours old)
  - Stories when blocked
  - Stories with visibility='archived'
  - GROUPS ARE NOT RELEVANT TO STORY VISIBILITY

==============================================================================
THE BUG IN CURRENT CODE
==============================================================================

File: lib/services/story_media_preload_service.dart

PROBLEM:
  _preloadVisibleGroupStories() queries the 'groups' collection to get
  group member IDs, then preloads stories from those users.
  
  But groups are CHAT GROUPS, not story visibility groups!
  
  The actual visibility is determined by ContactRepository.getContactIds()
  which returns:
    - Approved bidirectional contacts
    - Linked children (if parent)
    - Linked parents (if child)
  
  Groups and contacts are NOT the same set of users!

CONSEQUENCE:
  - Wrong stories may be preloaded (group members who aren't contacts)
  - Stories that should be shown may not be preloaded (contacts not in groups)
  - Wasted bandwidth on preloading stories user won't see
  - Performance degradation

THE FIX:
  Instead of:
    final userGroupsQuery = FirebaseFirestore.instance
        .collection('groups')
        .where('members', arrayContains: _currentUser!.uid)
        .get();
  
  Use:
    final contactIds = await _contactRepository.getContactIds();
  
  This already implements the correct logic and will match what's actually
  displayed in the UI.

==============================================================================
THREE SOURCES OF CONTACTS
==============================================================================

1. APPROVED BIDIRECTIONAL CONTACTS
   Collection: contacts
   Query: where users.arrayContains(currentUserId) AND status='approved'
   
   Example: User A and User B approve each other
   {
     id: "contact_abc",
     users: ["userId_a", "userId_b"],  // alphabetically sorted
     status: "approved"
   }
   
   Both can see each other's APPROVED stories only
   
2. LINKED CHILDREN
   Data: User document with linkedChildrenIds field
   Example:
   {
     id: "parent_123",
     linkedChildrenIds: ["child_1", "child_2"]
   }
   
   Parent can see ALL stories (approved, pending, rejected)
   Children can see parent's APPROVED stories only
   
3. LINKED PARENTS
   Reverse query: Find parents where linkedChildrenIds.contains(userId)
   
   Parents can see ALL stories from linked child
   Child can see parent's APPROVED stories

==============================================================================
STORY STATUS HIERARCHY
==============================================================================

UPLOADING   - Being uploaded to Storage (only creator sees)
PENDING     - Waiting for parent approval (only parents see)
APPROVED    - Visible to approved contacts & parents (feed, 24h)
REJECTED    - Parent rejected it (shows rejection reason, expires)
EXPIRED     - Story is >24 hours old (not visible)

Story Visibility Types:
TEMPORARY   - 24h in feed (default)
PERMANENT   - Saved to profile (visible indefinitely)
ARCHIVED    - Hidden from profile (not in feed)

==============================================================================
BLOCK STATUS
==============================================================================

Collection: blocked_contacts

Bidirectional check:
  IF user_a_blocks_user_b EXISTS OR user_b_blocks_user_a EXISTS
  THEN neither can see stories from the other

Implemented in: StoryStreamManager._getBatchBlockStatuses()

When A blocks B:
  - A doesn't see B's stories
  - B doesn't know they're blocked
  - B can still see A's stories (unless A blocks them back)
